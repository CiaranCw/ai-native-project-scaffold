# Understand mode notes

Progressive-disclosure support only. Not a second identity authority.

`bootstrap` owns first-attach Adoption. Generic “adopt this project” intent authorizes the Agent to enter Bootstrap, preview, and apply the generated `plan_id` / `plan_digest` when machine preconditions still hold; `--approved --plan-digest` is that apply request, not human Git Commit/Push. `full` owns P2 normalization. `refresh` owns stale-knowledge update and, when Submit hands off exact S3 impacts, publication of a candidate-bound Knowledge Assessment plus the current-head for that exact `(candidate_digest, impact_digest)` binding. A later Assessment for the same binding supersedes the previous Assessment. `refresh` also owns observational zero-context resume (`action=resume`) and authority-gated incremental understanding persist (`action=understand`). Physical currentness observation is not refresh-completion authority; persist requires Understand-produced supporting completion receipts bound to exact source/structural/output digests **and** current knowledge-file bytes. Missing or mismatched `result.yaml` is not current refresh authority. Receipts bind the final Understand-produced knowledge payload and do not grant mutation authority; knowledge writes still follow `project.yaml` GENERATED / MANAGED bounded region / HUMAN_OWNED preserve / UNKNOWN-or-CONFLICTING fail closed. Those are Refresh actions, not a fifth Understand mode. `compatibility` owns P4 evaluation, explicit lock-update planning, Migration Plan construction, and the canonical Migration Execution recovery machine. It does not start a fresh persistent Migration from Plan-only preview.
